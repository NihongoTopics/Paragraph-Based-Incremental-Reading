# ページの断片（frag/pNNNN.html）の書き方

SKILL.md の手順 4 で書くファイルの規則。図、表、数式のあるページは、`figures-tables-math.md`（6〜8 と例の 13）も読む。1 ページにつき 1 ファイル。assemble.py がこれを読んで 1 本の HTML にする。

規則の多くは アドオンの取り込みの動作から来ている。各項目の「理由」に書いた。根拠は、2026-09-25 に Anki 26.09.2（QtWebEngine 6.11.2、Chrome 140）で
確かめたものと、2026-10-15 に アドオンの取り込みの規則の写し（scripts/ir_rules.py、addon2/ir2/core.py から写したもの）で確かめたもの。
アドオンの取り込みダイアログは HTML のファイルを Mozilla Readability に通して本文を取り出し（2026-10-16 から）、題を h1 として
本文の前に置く。そのあと文書の直下の p とリストを 1 個ずつ `<div data-ir>` で包んでカードにする（core.segment）。
Readability は style と class の属性と、表示用とする属性（align, border, bgcolor, valign など。表の width と height も）を外す。
外れるもの、形が変わるものは書かない。check.py が、取り込みで外れる属性と、減るか形の変わる要素を誤りとして出す。

## 1 ファイル全体

- そのページの内容を、読む順に書く。`<html>`, `<head>`, `<body>` は書かない。
- 読む順は、ページの見た目の順ではなく本文の順。2 段組なら左の段を上から下まで読んでから右の段へ進む。
  段をまたぐ見出しや図は、それがページ上で占める位置で流れに入れる。
- 段落の途中に図や表が来る場合（段の途中に挟まっている場合）は、その段落を書き終えてから図や表を書く。
- 文字は PDF に書かれているとおりに書く。要約、言い換え、並べ替え、補いをしない。
  誤植も直さない。

## 2 書かないもの

- 柱（ページの上下に毎ページ出る雑誌名、章題、著者名）、ページ番号、トンボ、スキャンの汚れ。
  理由: `<p>` で書くとカードになり、同じ文のカードがページの数だけできる。
- 印刷されたページ番号は、ファイルの 1 行目に `<!-- page-label: 245 -->` と書く。assemble.py がdata-pdf-page の span
  （`data-page-label`）に入れる。ページ番号が印刷されていなければ書かない。

## 3 見出しと題の周り

- 文書の題は `<h1>`、節の見出しは `<h2>` から順に。見出しの番号（「3」「3.1」「第 2 章」）は見出しの文字に含める。
  理由: 見出しはカードにならず、文書には残って表示される（core.segment）。
- 著者、所属、日付、雑誌の巻号、受付日など、題の周りの行は `<p>` に 1 行ずつ書く（カードになる）。
  理由: 取り込みは中にブロックの無い div を p に替えるので（Readability の _grabArticle）、div で書いても p になる。
- 要旨は、「Abstract」などの見出しを `<h2>`、本文を `<p>` で書く（カードになる）。
- `class` と `id` は付けない（`ir-` で始まるものはアドオンの CSS と JS が使う）。

## 4 段落

- 本文の段落は `<p>`。1 段落が 1 枚のカードになる。
- 段をまたぐ段落（左の段の最後から右の段の最初へ続くもの）は 1 つの `<p>` に書く。
- 行末のハイフンで分けられた語は 1 語に戻す（"incre-" と "mental" → "incremental"）。
  もともとハイフンを持つ語（"well-known"）はハイフンを残す。どちらか決まらないときは、同じ文書のほかの箇所での
  書き方に合わせる。それでも決まらなければハイフンを残す。
- 日本語や中国語の行末は、つないだところに空白を入れない。
- ページの最初の段落が前のページの最後の段落の続きのときは、その段落に `data-pdf-cont` を付ける。
  - `data-pdf-cont="space"` … 空白 1 個でつなぐ（英語などで語の切れ目のとき）。
  - `data-pdf-cont="none"` … そのままつなぐ（日本語など。またはハイフンを残す語の途中）。
  - `data-pdf-cont="dehyphen"` … 前のページの末尾のハイフンを取ってつなぐ（行末のハイフンで分けられた語の途中）。
  前のページの末尾は、前のページの画像か frag で確かめる。
  リスト、表、引用がページをまたぐときは、その `<ol>`, `<ul>`, `<table>`, `<blockquote>` に `data-pdf-cont` を付け、
  途中で分かれた項目や段落があればその要素にも付ける。表の見出し行がページごとに繰り返されていれば、2 ページ目以降の見出し行は書かない。
- ブロックの要素（div, figure, table, ul, 見出しなど）を `<p>` の中に入れない。
  理由: 取り込みダイアログはファイルをブラウザ（DOMParser）で読むので、`<p>` の中のブロックの所で `<p>` が閉じる。
  ブロックとその後ろの文字は `<p>` の外に出て、別のブロックか別のカードになる。

## 5 リスト、引用、字下げに意味のある行

- 箇条書きと番号付きの項目は `<ul>` か `<ol>` の `<li>`。リスト全体（下位のリストを含む）が 1 枚のカードになる（core.segment）。
  学習画面で PBIR → Split を使うと、項目の境目でリストを分けられる。
- 印刷されている番号や記号（"1.", "(a)", "[3]", "•"）は `<li>` の文字の先頭に書き、リストの要素に
  `type="none"` を付ける（`<ol type="none">`）。番号をブラウザに付けさせない。PDF と同じ文字がカードに出る。
  assemble.py が type="none" を直下の各 `<li>` に移す。
  理由: 取り込みは style を外すので、`style="list-style-type: none"` は効かない。type は残る。HTML Standard の
  Rendering の節の Lists に `ul[type=none i], li[type=none i] { list-style-type: none; }` があり（ol は無い）、
  Chrome 154 で ul と li の type="none" が印を消し、ol の type="none" が消さないことを確かめた（2026-10-15）。
- 引用のブロックは `<blockquote><p>…</p></blockquote>`。blockquote は中の p も含めてカードにならない
  （pre と同じく表示はされる）。
- 行の位置を揃えることに意味があるもの（プログラム、字下げで揃えた例文、行ごとに揃えた対訳）は `<pre>`。
  空白と改行がそのまま残る。`<pre>` はカードにならない（見出しと同じく、隣の段落のカードで明るく出る）。

## 9 脚注

- 脚注は `<aside class="pdf-footnote">` の中の `<p>` で書き、合印（番号か記号）を先頭に `<sup>` で書く。本文の合印も `<sup>`。
  ```
  <p>… as noted before.<sup>2</sup> …</p>
  <aside class="pdf-footnote"><p><sup>2</sup> Equation numbers …</p></aside>
  ```
  脚注は、そのページの断片のどこに書いてもよい（ページの下のままでよい）。assemble.py が、同じページで同じ文字の `<sup>` の
  ある段落（リスト、表、図なら、その全体）のすぐ後へ移す。1 つの段落に脚注が幾つもあれば、段落の中の合印の順に並ぶ。
  そのあと aside を外し、脚注の `<p>` は本文の段落と並んで 1 枚のカードになる。
  理由: 脚注を、それを読む段落のカードのすぐ後のカードにするため。アドオンでは aside の中の p はカードにならない（core.segment）。
  aside に書くのは、assemble.py が脚注を見分け、次のページの続きをつなぐとき脚注を飛ばして本文の段落を探すため。
- 同じ文字の `<sup>` がページの二つ以上の段落にあるとき（`m<sup>2</sup>` など）は、脚注を合印のある段落のすぐ後に書く
  （ほかの脚注を挟んでよい）。そう書いてあれば assemble.py はそこに置く。そうでなければ移さずに警告する。
  合印の `<sup>` がページに無いときも、移さずに警告する。
- 合印のある段落が次のページへ続く場合も、脚注はそのページの断片に書く。assemble.py がページをまたぐ段落をつなぐと、
  脚注はつないだ段落の後に来る。
- 章末や巻末の注は、印刷されている場所のまま、番号を文字に含めて 5 の形で書く。

## 10 言語と書字の向き

- 文書全体の言語は assemble.py の `--lang` で決める。それと違う言語のブロックには `lang` を付ける
  （`<p lang="ja">`）。文の中の語句には `<span lang="ja">…</span>`。
  理由: `<html>` と `<body>` の lang は取り込みで消える（core.normalize は body の中身だけを残す）。
- 言語のコードは BCP 47。日本語 ja、簡体字中国語 zh-Hans、繁体字中国語 zh-Hant、韓国語 ko、アラビア語 ar、
  ヘブライ語 he、ギリシア語 el、ロシア語 ru、ヒンディー語 hi。中国語は簡体字か繁体字かを必ず分ける。
  lang は取り込みで残り、その要素の言語を示す。書体は付けない（style は取り込みで外れる）。lang だけでは QtWebEngine は
  中国語を日本語の書体（Hiragino Sans）で描く（2026-09-25 の検証）。
- 右から左へ書く言語（アラビア語、ヘブライ語など）のブロックには `dir="rtl"` も付ける。文の中の語句は
  `<span lang="ar" dir="rtl">…</span>`。文字は論理順（読む順）で書く。
  理由: dir が無いと語の並びが崩れる。dir は取り込みで残る。
- 縦書きの本文も、HTML では横書きで書く（読む順は縦書きのまま、右の行から）。

## 11 読めない箇所

- 画像を拡大しても（crop.py --zoom）読めない文字は、推測で埋めない。
  - 読みが 2 通り考えられる: `<span data-pdf-unclear data-alt="もう一つの読み">いちばん確からしい読み</span>`
  - 読めない: `<span data-pdf-unclear>[?]</span>`（字数が分かれば `[?]` をその数だけ）
  - 印は data- の属性にする（取り込みは class を外すが、data- の属性は残す）。

## 12 文字の飾りとリンク

- 斜体は `<i>`、太字は `<b>`、下線は `<u>`。PDF で飾りに意味がある箇所（書名、例文の語、強調）は残す。
  本文全体の書体の違いは写さない。小型大文字は、印刷された字の大文字と小文字のまま、飾りを付けずに書く。
- style（色、書体、小型大文字、揃え）と class は付けない。
  理由: 取り込みが外す（Readability の _cleanStyles と _cleanClasses）。
- リンク（`<a>`）は書かない。URL は文字として書く。
